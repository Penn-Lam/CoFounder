# Run the MVP on a Cloudflare full stack

Use one same-origin Cloudflare Worker with Hono to serve the existing React/Webpack applications and the product's backend interfaces. The imported IE-style application is served at `/desktop`, embedded by the 3D desktop experience, and opened directly on mobile. Use Better Auth with email OTP delivered by Resend, D1 for authentication and Pair data, R2 for oversized media and generated assets, a Queue for asynchronous report generation and transactional work, and a Cron Trigger for retention cleanup. All Pair, Answer, and Result operations cross a backend-owned domain interface rather than exposing the database to browsers; the browser renders the animated Identity Receipt while the backend deterministically renders its Open Graph image.

This favors one deployment and data plane over the faster managed combination of Supabase Auth/Postgres with Cloudflare or Vercel, and avoids Clerk's separate identity tenancy model. It requires replacing the current Express runtime, moving assets larger than Cloudflare's 25 MiB static-asset limit to R2, and accepting that an overseas MVP has no guaranteed mainland-China availability. The React 17/Webpack frontend remains in place so infrastructure migration does not expand into an unrelated UI rewrite.
